# Requirements Traceability Matrix

- **Product:** ClaimFlow – Department Expense Reimbursement System
- **Baseline:** `docs/srs.md` v0.3 · Features: `docs/features.md` v1.0 · Design: `docs/system-sds.md` v0.18 · Sprint 1 contracts: `docs/sprints/sprint-1/` · Sprint 2 contracts: `docs/sprints/sprint-2/` · Sprint 3 contracts: `docs/sprints/sprint-3/`
- **Last updated:** 2026-11-25

There is one row per SRS requirement. Each row traces requirement → feature or system responsibility → sprint → acceptance criteria → test → result. The design sections for each feature and responsibility are in section 4 of `docs/features.md`.

How to read and update the columns:

- **AC / Planned test:** filled from each feature contract. Sprint 1 IDs come from the Sprint 1 contracts in `docs/sprints/sprint-1/` (#6), Sprint 2 IDs from `docs/sprints/sprint-2/`, Sprint 3 IDs from `docs/sprints/sprint-3/`. `F02-AC-03` is AC-03 in the F-02 contract; `F02-TEST-04` is its TEST-04. Rows for Lab 5 stay `planned` until their contracts are written.
- **Actual test:** the test file and name that runs, e.g. `internal/claim/service_test.go › TestAct_SelfApproval`.
- **Result / Version:** `pass`, `fail`, `manual`, or `partial` (some planned tests pass, others have not run yet), plus the release tag or commit it was run on.
- **Ownership:** when a requirement is enforced by several features, the row lists all of them, and each feature's contract carries its own AC for its own paths.
