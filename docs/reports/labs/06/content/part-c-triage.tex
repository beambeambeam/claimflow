\textbf{Why \#86 is a defect.} F-02 §1.4 gives ``Enter a title (up to 120 characters).'' for an empty title, and the same for the other three fields. Text of only spaces is empty to a user, and the stored claim cannot be read or edited in Sprint 1.
The triage reproduced it on \texttt{f684459} in both layers: \texttt{POST /api/v1/claims} returned 201, because the contract had only \texttt{minLength: 1}, and the form checked only \texttt{min(1)}.
\textbf{Minor}: no money or access is affected, and the reviewer can reject the claim.

\textbf{Why \#87 is a defect.} F02-AC-13 requires Submit to be disabled while sending.
The triage reproduced it in a component test: two clicks in one tick sent two create requests, because Submit went busy only after \texttt{create.isPending} rendered.
\textbf{Major}: the requester does not see the duplicate, cannot withdraw it in Sprint 1, and the same expense can be approved and paid twice. A major defect blocks acceptance, so it had to be fixed and retested.

Server-side idempotency (an \texttt{Idempotency-Key} on \texttt{POST /claims}) is not part of the \#87 fix. SDS §7.2 puts double-submit prevention in the UI, and refusing identical content on the server would block legitimate identical claims. It would be a separate enhancement.
