\subsubsection*{A.1.5 Data setup}

\begin{itemize}
\tightlist
\item
  No setup by the UAT Team. Each deploy runs the seed, which creates the seven accounts and six sample claims (\texttt{CLM-2026-900001} to \texttt{CLM-2026-900006}).
\item
  The cases do not use the sample claims, because an earlier tester may have decided them. Each case creates the claims it needs in its first steps.
\item
  Give each claim the title in the case, with the case ID and your run number, for example \texttt{UAT-01 run 1 – Khon Kaen client visit}. Use run 2, 3, \ldots{} when you repeat a case. Then you can always find your own claim in a list.
\item
  All names, amounts, receipt references, and comments in the cases are synthetic. Do not enter real personal or financial data.
\item
  Dates are relative to \textbf{D}, the day you run the case in Asia/Bangkok time. \texttt{D-3} is three days before D. Enter dates as \texttt{YYYY-MM-DD}. Do not run UAT-02 within 10 minutes of midnight Bangkok time, because D changes.
\item
  Money is in Thai baht (THB) with 2 decimals. Enter \texttt{1250.50}; the app shows \texttt{THB 1,250.50}.
\end{itemize}

\subsubsection*{A.1.6 Reset and cleanup}

\begin{itemize}
\tightlist
\item
  Claims cannot be deleted in Sprint 1, and the claim history is append-only (BR-11). Claims made during UAT stay in the database. This is expected and does not affect a rerun, because each run uses a new title.
\item
  Claims that a case leaves in \texttt{Submitted} (UAT-02, 03, 04) stay in a reviewer\textquotesingle s queue. Leave them. The queue is oldest first, 20 rows per page: use the › arrow next to \texttt{Page X of Y} (tooltip \texttt{Go to next page}) to find a newer claim.
\item
  Always log out at the end of a case, and before you log in as another account in the same browser. Or use a separate private window for each account.
\item
  A session ends 8 hours after login. If the app shows the Login screen during a case, log in again with the same account and continue.
\item
  The Product Team does not reset the shared database during the UAT window. The cases do not need a reset.
\end{itemize}

\subsubsection*{A.1.7 Case order}

Every case is independent: it creates its own data and can run in any order, by either tester. Suggested order: UAT-07, UAT-01, UAT-02, UAT-03, UAT-04, UAT-05, UAT-06. UAT-06 has two sessions; start Session 1 early and run Session 2 at least 1 hour later.

\subsubsection*{A.1.8 Recording results and reporting findings}

\begin{itemize}
\tightlist
\item
  For each case record: case ID, tester name and team, date and time, tested version (the \texttt{version} from \texttt{/api/v1/health}), the inputs you used, the actual result of each step, and PASS, FAIL, or BLOCKED (with the reason).
\item
  Write what you saw in the actual result. Do not copy the expected result.
\item
  Take a screenshot at each step marked \shot{}.
\item
  Report each failure as a GitHub Issue on \url{https://github.com/beambeambeam/claimflow/issues}, with a title that starts with \texttt{{[}UAT{]}}; the Product Team adds the label \texttt{uat}. Give the case ID and step number, the tested version, the steps, the expected result, the actual result, and a screenshot. Then post the Issue link in \texttt{\#qa}.
\end{itemize}
