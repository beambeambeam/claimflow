\section*{Answer Part 1: CI and Quality Gate}

\textbf{CI workflow.} \file{.github/workflows/ci.yml} runs five jobs on every pull request and push: \texttt{code\_quality} (lint, format, types), \texttt{test} (web unit tests with coverage), \texttt{api} (Go tests against PostgreSQL, 100\% coverage gate), \texttt{build} (web build) and \texttt{image} (builds the production Docker image).

\textbf{C-01, passing PR.} \pr{74} (cloud-ready image and compose stack), CI \run{44115292575} on head \texttt{a642875}: all five jobs pass, the API suite reports 758/758 statements covered (100\%). Beam's review raised three findings, all fixed before merge.

\textbf{Required checks on \texttt{main}.} The \texttt{main}, sprint and lab rulesets require \texttt{code\_quality}, \texttt{test}, \texttt{api}, \texttt{build} and \texttt{image} to pass, one approval (stale approvals dismissed on new commits), the branch up to date before merging, and block force pushes and deletion; allowed merge methods are Merge and Squash, and \texttt{main} has no bypass actor. The rules are recorded in \file{docs/system-sds.md} \S9.1.

\section*{Answer Part 2: Docker and Reproducible Configuration}

\textbf{Image.} \file{Dockerfile} builds one image that holds the Go API and the built web app; \file{.dockerignore} keeps \texttt{.env}, \texttt{node\_modules} and build output out of the context. \file{docker-compose.yml} runs \texttt{db} (PostgreSQL), \texttt{migrate} (migrations and seed) and \texttt{app}, with ports bound to loopback.

\textbf{C-03, fresh build and running container with its database} (from the \pr{74} body; fresh clone, only \texttt{.env.example} copied and filled in; run on commits \texttt{da4ab03} and \texttt{23385c1}, host ports 18080/55433 because the defaults were taken):
\begin{Verbatim}[fontsize=\footnotesize,frame=single,framesep=4pt]
git clone https://github.com/beambeambeam/claimflow.git && cd claimflow
cp .env.example .env    # set SEED_USER_PASSWORD
APP_VERSION=$(git rev-parse HEAD) docker compose up --build -d
curl -s localhost:8080/api/v1/health
curl -s localhost:8080/api/v1/ready

migrate: applied 00001_auth.sql
migrate: applied 00002_claims.sql
migrate: seeded 7 users and 6 claims
health:  {"status":"ok","version":"23385c1447a76d2a5bb4a936ff28e7443c758116"}
ready:   200
\end{Verbatim}
\vspace{-4pt}
\texttt{/} and \texttt{/claims} serve \texttt{index.html} (no-cache), hashed assets are \texttt{immutable}, \texttt{/api/v1/nope} returns a JSON 404. A claim created through the API survived \texttt{docker compose restart app} and \texttt{docker compose up --build}.

\textbf{Configuration without secrets.} \file{.env.example} and \file{apps/api/.env.example} hold placeholders only; \file{apps/api/.env.schema} declares every variable and marks the sensitive ones. The environment variable table in \file{docs/labs/lab-05/deployment.md} lists each variable with its source: in Cloud Run, \texttt{DATABASE\_URL} and the seed password come from Secret Manager (Fig.~10a), never from the repository. Secret push protection is on, so a pushed key would be rejected.
